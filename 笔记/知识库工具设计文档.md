## 一、项目概述

### 1.1 项目定位

一个**轻量级、本地优先**的知识库与任务管理工具，专为技术工作场景设计：

- 记录日常工作任务，支持层级和状态管理
- 组织零散的技术知识点，多维度分类检索
- 汇总 AI 生成的内容，快速定位和复用
- 自动同步到 GitHub，数据完全自主可控

**核心理念**：本地存储 + 自动云备份 + 轻量体验

---

### 1.2 技术栈

| 层级 | 技术选型 | 理由 |
|------|---------|------|
| **后端** | Python 3.11 + FastAPI | 异步高性能，生态丰富，易于集成硬件相关脚本 |
| **数据库** | SQLite + FTS5 | 轻量级，全文搜索能力强，单文件部署 |
| **前端** | Vue 3 + Vite + TypeScript | 响应式，组件化，开发体验好 |
| **编辑器** | CodeMirror 6 | 现代化 Markdown 编辑器，可扩展性强 |
| **Git 集成** | GitPython | 自动提交推送，冲突检测 |
| **打包部署** | PyInstaller + Tauri（可选） | 单文件可执行程序，或原生桌面应用 |

# PWM调光方案

## 背景

光源模块需要支持 0-100% 的亮度调节...

## 技术方案

### 硬件实现
- 使用 TIM3 的 CH1 输出 PWM
- 频率：20kHz（避免可见闪烁）

### 软件实现
```c
void set_brightness(uint8_t percent) {
    uint16_t duty = (percent * TIM3_ARR) / 100;
    TIM3->CCR1 = duty;
}
```

## 测试结果

| 亮度(%) | 实测电流(mA) | 备注 |
|---------|-------------|------|
| 10      | 45          | 正常 |
| 50      | 220         | 正常 |
| 100     | 450         | 正常 |

## 相关资料

- [[通信协议设计#亮度控制命令]]
- 数据手册：`docs/LED_datasheet.pdf`

- 使用事件回调

### 2.2 数据库索引设计

#### 2.2.1 SQLite 表结构

**笔记索引表（notes）**：

```sql
CREATE TABLE notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    file_path TEXT UNIQUE NOT NULL,     -- 相对路径
    title TEXT,
    created DATETIME,
    modified DATETIME,
    type TEXT DEFAULT 'note',           -- note/task/ai-summary
    content TEXT,                        -- Markdown 正文（用于全文搜索）
    metadata TEXT                        -- JSON 格式的 frontmatter
);

-- 全文搜索虚拟表
CREATE VIRTUAL TABLE notes_fts USING fts5(
    title, content, 
    content='notes', 
    content_rowid='id',
    tokenize='unicode61 remove_diacritics 1'
);
```

**标签表（tags）**：

```sql
CREATE TABLE tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL
);

CREATE TABLE note_tags (
    note_id INTEGER,
    tag_id INTEGER,
    FOREIGN KEY (note_id) REFERENCES notes(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (note_id, tag_id)
);
```

**链接关系表（links）**：

```sql
CREATE TABLE links (
    source_id INTEGER,
    target_id INTEGER,
    link_text TEXT,                      -- 原始链接文本，如 [[PWM调光方案]]
    FOREIGN KEY (source_id) REFERENCES notes(id) ON DELETE CASCADE,
    FOREIGN KEY (target_id) REFERENCES notes(id) ON DELETE CASCADE,
    PRIMARY KEY (source_id, target_id)
);
```

**同步状态表（sync_status）**：

```sql
CREATE TABLE sync_status (
    file_path TEXT PRIMARY KEY,
    last_synced DATETIME,
    sync_hash TEXT,                      -- 文件内容的 SHA256
    status TEXT DEFAULT 'synced'         -- synced/pending/conflict
);
```

**同步策略**：

1. **文件变更检测**：使用 `watchdog` 监听文件系统事件
2. **防抖动**：编辑停止 30 秒后才提交（避免频繁 commit）
3. **提交信息**：自动生成，格式 `Auto: 更新 {文件名} (+{新增行} -{删除行})`
4. **推送策略**：
   - 本地 commit 后立即尝试 push
   - 网络失败时加入队列，下次联网时自动推送
   - 推送前自动 pull，有冲突时提示用户
5. **多设备冲突处理**：
   - 检测到冲突时标记文件，通知用户
   - 用户选择保留哪个版本或手动合并

## 四、部署方案

```bash

cd backend
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

### 4.2 本地运行

**方式一：开发模式**
```bash
# 后端（监听 8000 端口）
uvicorn main:app --reload --host 127.0.0.1 --port 8000

# 前端（监听 5173 端口，代理 API 到后端）
npm run dev
```

访问：`http://localhost:5173`

**方式二：生产模式**
```bash
# 打包前端
npm run build

# 后端直接服务前端静态文件
uvicorn main:app --host 127.0.0.1 --port 8765
```

访问：`http://localhost:8765`

### 4.3 打包部署

**单文件可执行程序（PyInstaller）**：
```bash
pyinstaller --onefile --add-data "frontend/dist:frontend/dist" main.py
```

生成 `dist/main.exe`，双击运行即可。

**桌面应用（Tauri，可选）**：
- 用 Rust + Tauri 包装 Web 前端
- 体积更小（~10MB vs Electron 的 150MB）
- 原生系统托盘、右键菜单

### 6.2 全文搜索优化

SQLite FTS5 配置：

```sql
CREATE VIRTUAL TABLE notes_fts USING fts5(
    title, 
    content,
    tokenize='porter unicode61 remove_diacritics 1',
    prefix='2,3'  -- 支持前缀搜索，至少 2 个字符
);

-- 搜索示例
SELECT * FROM notes_fts 
WHERE notes_fts MATCH '光源 AND 驱动' 
ORDER BY rank 
LIMIT 20;
```

### 6.3 性能优化

1. **惰性加载**：文件树只加载当前展开的节点
2. **虚拟滚动**：搜索结果列表使用虚拟滚动（1000+ 条时）
3. **增量索引**：只更新修改过的文件
4. **缓存策略**：
   - 文件内容缓存（LRU，最多 50 个）
   - 搜索结果缓存（5 分钟过期）
5. **异步处理**：Git 操作在后台线程执行

## 七、安全与备份

### 7.1 数据安全

1. **本地优先**：数据存在本地，离线完全可用
2. **Git 版本控制**：每次修改都有历史记录
3. **定期备份**：
   - 自动备份到 GitHub
   - 可选择额外备份到其他 Git 仓库（GitLab / Gitee）
4. **敏感信息**：
   - GitHub Token 存在系统 keyring
   - 不保存明文密码

### 7.2 冲突处理

**检测逻辑**：
```python
def detect_conflict(local_hash: str, remote_hash: str, base_hash: str) -> bool:
    """三路合并检测"""
    return local_hash != remote_hash and local_hash != base_hash and remote_hash != base_hash
```

**解决策略**：
- 自动合并：文本文件，修改不同部分
- 手动解决：修改同一部分时，展示 diff 让用户选择

## 九、风险与限制

### 9.1 已知限制

1. **大文件性能**：单个 Markdown 文件超过 10MB 时编辑会卡顿
   - 解决：提示用户拆分文件
2. **Git 冲突**：复杂冲突需要手动解决
3. **移动端**：浏览器访问体验一般，触摸优化有限
4. **网络依赖**：GitHub 同步需要稳定网络

### 9.2 备选方案

如果 GitHub 访问不稳定，可以切换到：
- Gitee（国内）
- 自建 Git 服务器
- 纯本地使用（不同步）
